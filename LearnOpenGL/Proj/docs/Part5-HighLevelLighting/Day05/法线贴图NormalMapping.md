# 法线贴图 Normal Mapping（Day 05）

对应 LearnOpenGL「[法线贴图](https://learnopengl-cn.github.io/05%20Advanced%20Lighting/04%20Normal%20Mapping/)」：漫反射贴图只能改颜色，光照仍把表面当成一块平板——砖缝、孔洞接不到光。真正决定「朝哪」的是**法线**。给每个片元一张图里的法线，不增加三角形也能让光照以为表面凹凸不平。贴图里的法线定义在**切线空间**（永远偏 +Z），要用 TBN 把光照和这张图对上。

## 1. 为什么砖墙看起来是平的

光照只看法线。一个四边形四个顶点法线都是 `(0,0,1)`，插值后每个片元仍是同一方向，灯只能照出一块均匀的板。砖缝在漫反射图上是深色，但 `N·L` 不变，凹处不会自己变暗。

解决：每个片元换一条法线。不增加顶点，从一张图里读。砖缝朝两侧偏、孔朝里偏，光照就会在缝里变暗、在凸起上打出高光。高精度模型能换成低面数 + 法线图，远看差不多。

---

## 2. 法线图里存的不是颜色

法线是 `[-1,1]` 的 xyz，纹理是 `[0,1]` 的 rgb：

```
写入贴图:  rgb = n * 0.5 + 0.5
读出来:    n   = rgb * 2.0 - 1.0
再 normalize
```

所以法线图发蓝：多数向量靠近 `(0,0,1)`，对应偏蓝。砖顶沿 +Y 的会偏绿。这是**数据贴图**，不要标 `GL_SRGB`（Day02：只有 albedo 才是 sRGB）。

朝 +Z 的平面直接用法线图当世界法线能看对。把同一张图贴到朝 +Y 的地面就不对了：图里仍朝 +Z，几何却朝 +Y。不能为每个朝向各做一张图。办法是规定：**图里的法线永远相对「这块三角形的表面」**，再把光照变到这个局部空间，或把法线变到世界。这个局部空间就是切线空间。

## 3. 切线、副切线与 TBN

### 3.1 要解决什么问题

法线图里的向量约定是：

- `(0, 0, 1)`：垂直表面往外（没凹凸）
- \(x\) 偏了：沿纹理 **U** 那一侧歪
- \(y\) 偏了：沿纹理 **V** 那一侧歪

图自己不知道这面墙在世界里朝哪。墙朝 +Z、朝天、斜着，图都是同一张蓝图。

几何法线 \(N\) 只告诉你「哪边是外」。还缺两样：

- 贴图的 **右** 在空间里朝哪 → **切线 \(T\)**
- 贴图的 **上** 在空间里朝哪 → **副切线 \(B\)**

有了 \(T,B,N\) 三根轴，才能把「图里的法线」和「世界里的灯」搬到同一个房间里再点积。**缺的不是凹凸公式，是凹凸相对哪一组轴。**

没有 \(T,B\) 时，只能假设图里的 +Z 就是世界 +Z。平面刚好朝前时碰巧对；一转到侧面，砖缝明暗就拧了。

### 3.2 怎么定义

这里的切线**不是**微积分里曲线的 \(f'(x)\)，而是贴在三角形上的两根轴，由 **几何 + UV 铺法** 决定：

| 向量 | 名字 | 定义 |
|------|------|------|
| \(N\) | 法线 | 垂直于三角形（顶点法线，或两边叉乘） |
| \(T\) | 切线 tangent | 表面上 **U 增加** 的方向 |
| \(B\) | 副切线 bitangent | 表面上 **V 增加** 的方向 |

「U 增加」= 纹理坐标往右走一格，空间里的点往哪移动。砖墙图的左右缝应对着 \(T\)，上下缝对着 \(B\)。墙转到地面上、UV 旋转 90°，\(T,B\) 跟着转，不跟世界 XYZ 绑死。

### 3.3 和「切平面」的关系

三角形所在的平面叫**切平面**。\(T\) 和 \(B\) 都躺在这个平面上，\(N\) 垂直于它。所以：

| 向量 | 在切平面上的角色 |
|------|------------------|
| \(T,B\) | 平面里的「右 / 上」，由 UV 对齐 |
| \(N\) | 平面的「外」 |

三者一起 = 这块表面的局部世界。法线贴图只在这个小世界里说话；TBN 负责翻译。

采样出的切线空间法线 \(n=(n_x,n_y,n_z)\) 意思是：

```
n_世界 = n_x * T + n_y * B + n_z * N
```

\(n_z \approx 1\) 几乎就是几何法线；\(n_x>0\) 往纹理右侧歪。本 Demo 走等价的另一条路：不把 \(n\) 变到世界，而把灯变到切线空间，\(n\) 保持分量去点积。基底还是这三条轴。

### 3.4 为什么能从边和 UV 解出 T、B

顶点数据里通常已有位置、法线、UV，**没有现成的 T、B**。不能随便拿世界的「右 / 上」——墙一转就不对。必须问：对这块三角形，纹理往右走，空间里实际往哪走？答案藏在 UV 里。

从顶点 1 走到顶点 2，同一段位移有两种记账，必须相等（否则砖缝在空间里的朝向和贴图对不上）：

| 记账方式 | 写法 |
|----------|------|
| 用位置 | \(E_1 = P_2 - P_1\) |
| 用纹理 | UV 走了 \((\Delta u_1,\Delta v_1)\)，即 \(\Delta u_1 T + \Delta v_1 B\) |

所以 \(E_1 = \Delta u_1 T + \Delta v_1 B\)。一条边两个未知数，再写第二条边 \(E_2\)（1→3），解线性方程组。矩阵形式只是一次解出整条向量；代码里 `f` 是 UV 矩阵行列式的倒数（UV 退化、三点贴图像素叠在一起时除零，这个三角没有切线空间）。

对本 Demo 朝 +Z 的墙、普通 0～1 UV，结果应接近 \(T=(1,0,0)\)、\(B=(0,1,0)\)，再加 \(N=(0,0,1)\)。斜面或 UV 拧过的三角心算解不出，才用同一套公式。`calcTangentBitangent` 对两个三角各算一次，写入 location 3 / 4。Assimp 的 `aiProcess_CalcTangentSpace` 做的是同一件事，再在共享顶点上平均；`Mesh` 里已经留了这两个属性。

### 3.5 TBN 怎么用、为什么要正交化

**用法一**：`TBN` 把切线空间法线乘到世界，光照仍在世界空间算。  
**用法二（本 Demo）**：正交矩阵 `TBN⁻¹ = transpose(TBN)`，顶点着色器里把灯、相机、片元变到切线空间。片元里法线保持切线空间，少做矩阵乘法（顶点比片元少）。

共享顶点时 T 被平均，T、N 可能不再垂直。Gram-Schmidt：先让 T 相对 N 正交，再叉乘得到 B（与 `normalMapping.vs` 一致）：

```
T = normalize(T - dot(T, N) * N)
B = cross(N, T)
```

CPU 算出的 `aBitangent` 可以当参考；进 TBN 的 B 以叉乘为准，避免三条轴不再垂直。

### 3.6 为什么这样用就能对齐两个空间

能解决「贴图空间和世界空间朝向不一致」，不是因为多了两个名字，而是因为 **\(T,B,N\) 本身就是用这块三角的 UV 在世界里量出来的三根轴**。用法线图时用的是同一套 UV；TBN 把「图里的左右」翻译成「空间里的左右」。

不一致卡在 \(N\cdot L\)：两个向量必须同一坐标系。法线图采出的 \(n\) 住在切线空间（它的 +Z 永远是「垂直这张图」）；`lightPos`、片元位置住在世界。墙一转，世界的「外」变了，图里的 `(0,0,1)` 还是「相对表面往外」。直接点积等于两本字典对读。

顶点着色器里的用法（`normalMapping.vs`）：

1. `aTangent` / `aNormal` 来自 CPU：\(T\) 是「U 增加时，这个三角在物体空间里往哪走」。
2. 乘法线矩阵：墙怎么 `model` 旋转，三根轴跟着转到**当前世界朝向**。
3. `mat3(T, B, N)` 的三列 = 世界里的「贴图右、贴图上、表面外」。
4. `transpose` = 这组轴的逆：把世界坐标写成「沿 T、沿 B、沿 N 各多少」。

于是 `TangentLightPos` 不是「灯在房间的 XYZ」，而是「灯相对这块砖：偏右多少、偏上多少、偏外多少」。片元位置同样被写成这组分量。

片元里法线**不用搬**：`texture(normalMap, TexCoords)` 用的 UV，和当初解 \(T,B\) 用的是同一套铺法。图里的 \(n_x\) 就是「沿 \(T\) 歪」，而 \(T\) 正是「U 增加的世界方向」。点积这时比的是同一句话。墙在转：`model` 变 → T、B、N 在世界里转 → 灯被重新投影到新的切线空间。法线图不用换，砖缝仍贴着纹理。

三件事必须绑在一起：

1. **采样**：`normalMap` 用 UV 取值，\(n_x,n_y\) 表示沿 U / 沿 V。
2. **定义**：\(T,B\) 从同一套 UV 和三角形边解出（「U 动 → 空间怎么动」）。
3. **应用**：TBN 用这两根轴（再加 \(N\)）当基，把灯（或把 \(n\)）换到另一边。

轴是用 UV 量的，图也是用 UV 采的，翻译矩阵用的就是这两根轴——贴图空间和世界空间从此有一本共用字典。用法一是 `n_world = mat3(T,B,N) * n`（把图译成世界）；本 Demo 是把灯搬进图的语言。正用 / 反用同一本字典。

只算了 \(T,B\) 却不拿它们去乘灯或乘 \(n\)，字典编了没用，朝向不一致还在。`1` 键强制 \(n=(0,0,1)\)：切线空间里没有凹凸，翻译之后就是纯几何法线，TBN 仍在工作，只是图没开口。`2` 才是字典 + 法线图一起用。

### 3.7 记住这三句就够

1. **干什么**：给法线图提供「右、上、外」三根轴。
2. **解决什么**：贴图空间和世界空间朝向不一致。能解决，是因为轴用 UV 量、图用 UV 采、TBN 用这两根轴做翻译（见 3.6）。
3. **怎么定义**：\(T\) 跟着 U，\(B\) 跟着 V，\(N\) 垂直表面。

## 4. 和本工程怎么接

### 4.1 画面与按键

砖墙四边形绕轴慢转，点光在斜上方（小白立方体）。转到侧面仍应看得到砖缝明暗，说明切线空间对齐了，不是写死朝 +Z。

| 键 | 作用 |
|----|------|
| `1` | 几何法线（切线空间里固定 `(0,0,1)`），墙是平的 |
| `2`（默认） | 采样法线图，切线空间 Blinn-Phong |
| `3` | 把解包后的法线显示成颜色（偏蓝、缝处偏色） |
| WASD、鼠标、滚轮、Esc | 与前面几章相同 |

### 4.2 着色器

顶点：世界位置；Gram-Schmidt 得到 TBN；把 `lightPos` / `viewPos` / `FragPos` 乘 `transpose(TBN)` 送到片元。

片元：

```
n = texture(normalMap, uv).rgb * 2 - 1
normalize
L、V 用切线空间里的灯/相机/片元相减
其余 Blinn-Phong 与 Day01 相同
```

相关文件：`src/cppfile/main.cpp`，`shaders/Part5-HighLevelLighting/Day05-NormalMapping/`。`Mesh` 的 location 3 / 4 已为以后给 backpack 用法线图留好。

## 5. 容易踩的坑

| 现象 | 原因 |
|------|------|
| 转到侧面光照全错 | 没用 TBN，把切线空间法线当世界法线 |
| 明暗和砖缝对不上 / 反了 | 漫反射和法线一张 flip 一张没 flip；或切线/UV 镜像没处理 |
| 法线发灰、光照爆 | 忘了 `* 2 - 1`，或把法线图标成了 sRGB |
| 缝是对的、整体偏一边 | T、N 不正交，没 Gram-Schmidt |
| 加载的 obj 没有凹凸 | Assimp 没开 `CalcTangentSpace`，或法线槽在 `HEIGHT` 而不是 `NORMAL` |
