## 0. 术语中英对照

| 英文 | 中文 | 一句话 |
|------|------|--------|
| Depth buffer / Z-buffer | **深度缓冲** | 每个像素存一个「有多远」的值，通常 24 位 float |
| Depth testing | **深度测试** | 新片段的深度 vs 缓冲里的深度，决定留谁 |
| Depth value | **深度值** | 片段在屏幕空间里的 z，一般在 \[0, 1\] |
| Nonlinear depth | **非线性深度** | 投影后写入缓冲的弯曲线编码；近密远疏 |
| Linear / eye / view depth | **线性深度（观察 z）** | 线性化后 ≈ 相机正前方多远（view-space \(\lvert z\rvert\)） |
| Euclidean distance | **欧氏距离** | \(\sqrt{x^2+y^2+z^2}\)，相机到片元的斜线长度 |
| Depth function | **深度函数** | 比较规则，如 `GL_LESS` |
| Depth mask | **深度掩码** | 是否允许写入深度缓冲 |
| Early depth test / Early-Z | **提前深度测试** | 尽量在片段着色器**之前**做深度测试，省 FS |
| Pre-Z / Z-prepass | **深度预通道** | 先画一遍只写深度，再正式着色 |
| Z-fighting | **深度冲突** | 两个面几乎共面，深度精度不够，画面闪烁 |
| `gl_FragCoord.z` | **片段深度** | 片元着色器里可读的屏幕空间深度 |

## 1. 为什么需要深度测试？

画 3D 时，三角形提交顺序往往是乱的：可能先画远处的墙，再画近处的箱子。  
**颜色缓冲**只知道「最后画到这个像素的是什么颜色」，不知道谁该在前面。

所以窗口系统再准备一块和屏幕同尺寸的缓冲——**深度缓冲**：

- 颜色缓冲：每个像素的颜色（你看见的画面）
- 深度缓冲：每个像素当前「最近」物体的深度

直觉：

```
同一个像素上先后来了两个片段：
  A：深度 0.3（更近）
  B：深度 0.8（更远）

若比较规则是「更小的深度获胜」（GL_LESS）：
  先到 A → 通过，颜色=A，深度缓冲写成 0.3
  再到 B → 0.8 不小于 0.3 → 丢弃 B，画面仍是 A
```

没有深度测试时，**后画的永远盖住先画的**，和真实前后无关。

## 2. 深度测试在管线的哪一步？

简化后的片段路径（与官网一致，并标出 Early-Z 的位置）：

```
顶点着色器 → 光栅化产生片段
        │
        ├─【可选】Early-Z：若深度已定且 FS 不改深度
        │         失败则直接丢弃，根本不跑片段着色器
        │
        ▼
片段着色器（算光照、贴图……通常很贵）
        │
        ▼
模板测试（下一节） / 深度测试（若尚未 Early 掉）
        │
        ▼
通过则更新颜色缓冲；按规则更新（或不更新）深度缓冲
```

要点：

1. 深度测试用的是**屏幕空间**深度，和 `glViewport` 相关。  
2. 片元着色器里可用内建变量 `gl_FragCoord`：  
   - `.xy`：像素坐标（左下为原点）  
   - `.z`：该片段的深度值（要拿去和深度缓冲比的那个）

官网强调：**深度缓冲通常在片段着色器之后**做「标准」深度测试；但现代 GPU 常做 **Early Depth Testing**，在 FS **之前**就丢掉肯定看不见的片段，避免白跑昂贵的着色器。

## 3. 启用、清除、只读深度——本工程已有的最小用法

### 3.1 开启

深度测试**默认关闭**。本工程：

```cpp
glEnable(GL_DEPTH_TEST);
```

### 3.2 每帧清除

启用后，必须在每帧开始时清深度，否则会沿用上一帧的深度，画面会花：

```cpp
glClear(GL_COLOR_BUFFER_BIT | GL_DEPTH_BUFFER_BIT);
```

只清颜色、不清深度 → 典型翻车。

### 3.3 深度掩码（只测不写）

有时你想：**仍然按深度丢片段，但不更新深度缓冲**（只读深度）：

```cpp
glDepthMask(GL_FALSE);  // 禁止写深度
// ... 画一些东西（如半透明、或某些特效通道）
glDepthMask(GL_TRUE);   // 恢复可写
```

注意：只有深度测试已启用时，掩码才有意义。

## 4. 深度函数 `glDepthFunc`

比较「新片段深度」和「缓冲里已有深度」的规则可以改：

```cpp
glDepthFunc(GL_LESS);  // 默认
```

| 函数 | 含义 |
|------|------|
| `GL_ALWAYS` | 永远通过（效果≈没开深度测试：后画盖先画） |
| `GL_NEVER` | 永远不通过 |
| `GL_LESS` | 更近（更小）才通过 ← **默认** |
| `GL_LEQUAL` | 小于等于通过 |
| `GL_EQUAL` | 相等才通过 |
| `GL_GREATER` / `GL_GEQUAL` | 更远才通过（少见，特殊效果用） |
| `GL_NOTEQUAL` | 不等才通过 |

### 4.1 小实验：`GL_ALWAYS`

```cpp
glEnable(GL_DEPTH_TEST);
glDepthFunc(GL_ALWAYS);
```

深度测试永远过 → 最后画的东西总盖在上面。  
若地板最后画，就会盖住箱子——官网示例正是如此。改回 `GL_LESS` 恢复正常。

### 4.2 和本工程的关系

当前 `main.cpp` 只用默认 `GL_LESS`，没有显式 `glDepthFunc`；行为就是「近的留下」。

## 5. 深度值从哪来？为什么不是线性的？

### 5.1 先记住一句话（核心理解）

深度缓冲里存的，**通常不是**「摄像机到片元的欧氏距离」，也**不是**用简单直线比例算出来的距离。

它是透视投影之后的 **非线性深度**（可以想成一条**曲线**：近处变化快，远处被挤在一起）。

目的：**把有限的精度（如 24 位）多分配给近处**，让近处「谁挡谁」判得更准。  
这里的「更准确」主要指 **遮挡判断更准**，不是说它更像一把精确的米尺。

若要当「前方距离」用，才做线性化（本工程 `depthTest.fs` 里的 `LinearizeDepth`，Unity 里类似 `LinearEyeDepth`）。

### 5.2 三种「远近」不要混

相机在观察空间原点、朝前方看时，同一个片元 \(P=(x,y,z)\) 可以谈三种量：

```
              片元 P（屏幕边缘）
             /
            /  ← 欧氏距离：sqrt(x²+y²+z²)，斜线长度
           /
相机 C ----+----→ 正前方
           |
           |  ← view-space |z|：只沿「正前方」量到的深度
           v
```

| 名字 | 含义 | 典型来源 |
|------|------|----------|
| **非线性深度** | 缓冲 / `gl_FragCoord.z`，\[0,1\]，弯的 | 硬件深度测试用的值 |
| **线性深度（view z）** | ≈ 眼睛**正前方**多远 | `LinearizeDepth(gl_FragCoord.z)` |
| **欧氏距离** | 到片元的真实斜线长 | `length(相机 - 片元)`，要自己算 |

只要片元不在正中央（有 \(x\) 或 \(y\)）：

\[
\sqrt{x^2+y^2+z^2} \;\;>\;\; |z|
\]

所以：**线性化之后 ≈ view-space z，一般仍不是 \(\sqrt{x^2+y^2+z^2}\)**。  
屏幕正中间的像素两者几乎一样；靠边才明显。

生活类比：站在房间中间看墙——「到墙的前后距离」和「到墙角的斜线距离」不是一回事。深度缓冲主要管前后遮挡，用 view z / 投影深度就够了。

### 5.3 缓冲里是 \[0, 1\]

深度缓冲存的是 **0～1** 之间的值。观察空间里物体的 z 在 near～far 之间，投影时会被变到这个范围。

若**线性**映射（教学对比用，实际几乎不用）：

\[
depth = \frac{z - near}{far - near}
\]

近处 → 接近 0，远处 → 接近 1。这是「直线比例」；真实管线**不这么写进缓冲**。

### 5.4 透视投影用的是非线性（∝ 1/z）——就是那条「曲线」

真正嵌入投影矩阵的，是和 **1/z** 成正比的非线性映射。效果是：

- **近处**：深度精度很高（很小一段距离占很多 bit）
- **远处**：精度变差

这很合理：你更在乎眼前模型谁挡谁，不需要对 1000 米外的两面墙用同样精度。

管线直觉：

```
观察空间 z（线性，前方距离）
        ↓ 透视投影（弯一下）
NDC / 屏幕空间深度
        ↓ 映射到 [0, 1]
写入深度缓冲 ← gl_FragCoord.z
```

后果：

- 深度缓冲里的 `0.5` **不等于**「场景深度正好一半」
- 绝大多数远处片段的 `gl_FragCoord.z` 会挤在接近 `1.0` 的区域
- 直接把 `gl_FragCoord.z` 当颜色画，场景常常一片白；凑近才渐渐变暗——正好说明「曲线把精度堆在近处」

### 5.5 可视化深度（着色器演示）

直接输出非线性深度：

```glsl
#version 330 core
out vec4 FragColor;

void main()
{
    // 非线性深度：场景往往一片白，凑近才渐渐变暗
    FragColor = vec4(vec3(gl_FragCoord.z), 1.0);
}
```

线性化后再映射成灰度（near/far 要和投影一致）。本工程正式用法在 `shaders/depthTest.fs`：

```glsl
float LinearizeDepth(float depth)
{
    float z = depth * 2.0 - 1.0; // 回到 NDC
    return (2.0 * near * far) / (far + near - z * (far - near));
}

// linearDepth ≈ 观察空间前方距离（view z）
// 再除以 visualizationRange 只是为了显示好看，不改变真实深度测试
float gray = clamp(LinearizeDepth(gl_FragCoord.z) / visualizationRange, 0.0, 1.0);
FragColor = vec4(vec3(gray), 1.0);
```

`main.cpp` 里用 `DEPTH_VISUALIZATION_ENABLED` 固定走深度可视化路径；`CAMERA_NEAR_PLANE` / `CAMERA_FAR_PLANE` 必须与 `glm::perspective` 一致。

> Unity 对照：`_CameraDepthTexture` 采到的多半是非线性深度；`LinearEyeDepth` ≈ 这里的 `LinearizeDepth`（前方距离），一般仍不是欧氏斜线距离。

## 6. 深度冲突（Z-fighting）

两个三角形几乎**贴在同一深度**（共面或极近平行）时，深度缓冲位数不够区分谁在前，像素会来回闪——像在「打架」。

典型场景：箱子底面和地板同一高度。

### 缓解手段（官网三条 + 实务习惯）

1. **别让面重叠**：箱子略抬高一点（肉眼难察的偏移即可）。  
2. **near 不要太近**：near 过小会浪费大量精度在极近处，远处更易冲突；但 near 太大又会裁掉近景。  
3. **更高精度深度缓冲**（如 32 位，若硬件/上下文支持）。  
4. （实务）绘制顺序、polygon offset（`glPolygonOffset`）等进阶手段，以后遇到再学。

深度冲突无法 100% 消灭，组合使用上述技巧通常够用。

## 7. Early-Z 与 Pre-Z（深入浅出）

官网提到 **Early Depth Testing**：能提前丢弃永远看不见的片段，避免跑片段着色器。  
引擎/图形程序员口中还有 **Pre-Z（Z-prepass）**。两者相关但不是同一个开关。

### 7.1 Early-Z：硬件尽量「先比深度，再着色」

**目的**：片段着色器很贵（光照、多贴图、分支）。若一个像素已经被更近的三角形占住，后面更远的片段就算完光照也没用。

**理想路径**：

```
光栅化 → 深度已经可判定
       → Early-Z 失败 → 丢弃（不跑 FS）
       → Early-Z 通过 → 再跑 FS → 写颜色（并可能写深度）
```

这是 **GPU / 驱动的优化**，不是你调用的某个 `glEnable(GL_EARLY_Z)`。  
你能做的是：**写出不挡 Early-Z 的着色器与状态**，让硬件放心得提前测。

### 7.2 Pre-Z / Z-prepass：软件主动「先画一遍深度」

**Pre-Z** 是一种**渲染策略**（常用于复杂场景）：

```
第 1 遍（Z-prepass）：
  深度测试开、深度可写
  用极简或空片段着色器（甚至只写深度）
  把场景不透明物体的深度填进深度缓冲

第 2 遍（着色）：
  深度测试仍开，常设为 GL_EQUAL 或 GL_LEQUAL
  深度掩码可关掉（glDepthMask(FALSE)）——深度已定好
  跑真正昂贵的光照 FS
  → 大部分被挡住的像素在 Early-Z / 深度测试阶段就被挡掉
```

类比：

| 概念 | 类比 |
|------|------|
| Early-Z | 餐馆厨房的规矩：看清这桌已经上过菜了，就别再做同一道 |
| Pre-Z | 先上桌摆好「占位牌」（深度），再正式炒菜（着色） |

Pre-Z **帮助** Early-Z 更有效：第一遍把「最近深度」填满后，第二遍昂贵 FS 只服务真正可见的像素。

本工程目前是单通道前向渲染，**没有**单独做 Z-prepass；背包场景三角形不多，不必上。等以后场景复杂、片元着色器变贵时再考虑。

### 7.3 Early-Z 什么时候会失效？为什么？

核心原则：**硬件必须在跑 FS 之前就知道最终深度**。  
凡是「深度要等 FS 跑完才知道」或「深度/覆盖规则太花」的情况，Early-Z 就会被关掉或弱化，退回「先着色再测深度」。

| 情况 | 为什么 Early-Z 容易失效 |
|------|-------------------------|
| **FS 改写深度**（写 `gl_FragDepth`） | 最终深度由着色器决定，无法提前比 |
| **Alpha Test / `discard`** | 片段是否存在要等 FS 决定；有的实现仍可能部分优化，但不能假定一定 Early-Z |
| **开启 Alpha 混合且顺序敏感** | 不只比远近，还要按透明规则叠加；常与「只留最近」的 Early-Z 目标冲突 |
| **关闭深度测试 / 深度函数很怪** | 没有「近者优先」的稳定假设 |
| **`glDepthMask(FALSE)` 且某些组合** | 只读深度时，部分路径仍可 Early-Z 做剔除，但写入策略变了；和「完整 Early-Z 写深度」不同 |
| **模板测试改写复杂、部分扩展/关闭优化** | 与深度强耦合时，驱动可能保守关闭 Early-Z |
| **开启 conservative depth 以外的随意改深度** | 同「改写深度」 |

OpenGL / GLSL 侧可记两条实务规则：

1. **别随便写 `gl_FragDepth`**。若必须写，可用 `layout(depth_*)` 等 **conservative depth** 声明，告诉硬件「深度只会更近/更远」，有机会保留 Early-Z（进阶，此处略）。  
2. **不透明物体：先画、深度写开、FS 别 discard**；半透明：另开通道，常关深度写入、注意排序——和 Early-Z 目标不同。

### 7.4 Pre-Z 什么时候不划算或会「失效」？

Pre-Z 不是硬件开关，而是多画一遍的**成本换收益**：

| 情况 | 说明 |
|------|------|
| 场景很简单、FS 很便宜 | 多一遍几何可能更亏（本工程背包 Demo 通常如此） |
| 大量透明物体 | Z-prepass 主要服务不透明；透明仍要排序/特殊处理 |
| 几乎每个像素都改深度 / discard | 第二遍也难 Early-Z，预通道收益变小 |
| CPU/带宽已经吃满在几何上 | 双倍 draw call / 顶点开销可能成为新瓶颈 |

「失效」在这里更多指：**收益没了或策略不再适用**，而不是某个 API 报错。

### 7.5 一张总表：标准深度测试 vs Early-Z vs Pre-Z

| | 标准深度测试 | Early-Z | Pre-Z |
|--|--------------|---------|-------|
| 谁发起 | OpenGL 状态机 | GPU/驱动优化 | 你的渲染循环设计 |
| 何时比深度 | 通常在 FS 后（逻辑上） | 尽量在 FS 前 | 第一遍专门写深度 |
| 你要写的代码 | `glEnable` / `glDepthFunc` / `glClear` | 遵守「不挡优化」的写法 | 两遍绘制 + 合适的 depth func/mask |
| 主要收益 | 画面前后正确 | 少跑 FS | 复杂场景下放大 Early-Z 收益 |

## 8. 推荐动手实验（对照官网）

在现有工程上可以做的小实验（不必一次全做）：

1. **注释掉** `glEnable(GL_DEPTH_TEST)`：观察模型是否前后错乱。  
2. **只** `glClear(GL_COLOR_BUFFER_BIT)`：不清深度，拖动相机看残影/错乱。  
3. 临时 `glDepthFunc(GL_ALWAYS)`：后画覆盖先画。  
4. 对比直接输出 `gl_FragCoord.z` 与本工程 `depthTest.fs` 的线性化灰度，体会「曲线」和「前方距离」。  
5. 把两个物体叠到几乎同一深度，观察 Z-fighting，再给其中一个加一点点位移。

## 10. 小练习

1. 深度缓冲和颜色缓冲分别存什么？少清哪一个会出现什么现象？
