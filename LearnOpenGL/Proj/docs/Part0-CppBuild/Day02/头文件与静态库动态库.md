## 0. 术语中英对照

| 英文 | 中文 | 一句话 |
|------|------|--------|
| Header | **头文件** | `.h` / `.hpp`，声明「有什么接口」 |
| Library | **库** | 别人写好、给你用的代码（已编或源码） |
| Static library | **静态库** | `.a`（MinGW）/ `.lib`（MSVC），链接时打进 `.exe` |
| Dynamic library / Shared library | **动态库** | `.dll`（Windows）/ `.so`（Linux），运行时再加载 |
| Prebuilt | **预编译库** | 别人或你事先编好的 `.a`/`.lib`，工程里直接链接 |
| Header-only | **纯头文件库** | 几乎没有 `.a`，实现也在头里（如 GLM） |
| Include path | **头文件搜索路径** | 编译器去哪找 `#include` 的文件 |

## 1. 头文件是「说明书」，不是「整台机器」

你写：

```cpp
#include <assimp/Importer.hpp>
Assimp::Importer importer;
```

编译器需要知道：

- 有没有叫 `Assimp::Importer` 的类？
- 构造函数怎么写？有哪些成员函数？

这些信息写在 **头文件**里。  
真正「干活」的机器码，往往在 **库文件**（`.a`）里，链接阶段才拼进来。

类比：

| 东西 | 类比 |
|------|------|
| 头文件 `Importer.hpp` | 面包店菜单：有什么、怎么点 |
| 静态库 `libassimp.a` | 已经烤好的面包（功能实现） |
| 你的 `main.cpp` | 你点餐、自己写的业务 |

**只有菜单没有面包** → 链接失败（找不到符号）。  
**只有面包没有菜单** → 编译失败（不知道怎么调用）。

所以预编译依赖通常成对出现：

```
Depends/prebuilt/
  include/assimp/...     ← 菜单
  lib/libassimp.a        ← 面包
```

## 2. 三种常见「给别人用代码」的方式

### 2.1 纯头文件（header-only）

例如本工程的 **GLM**：

```cpp
#include <glm/glm.hpp>
glm::vec3 v(1.0f, 2.0f, 3.0f);
```

几乎没有单独的 `.a`。实现都在头里，include 进来编译器直接看到。  
优点：接入简单；缺点：改一次可能编译变慢（头很大）。

### 2.2 静态库（本工程 Assimp / GLFW 采用）

```
编译你的代码时：读头文件
链接时：把 .a 整份拷进 main.exe
运行时：一般不再需要旁边再放一份 Assimp.dll
```

优点：发布简单，少管 DLL。  
缺点：`.exe` 变大；换编译器后要重新编这份 `.a`。

### 2.3 动态库

```
链接时：只记下「将来去找某某.dll」
运行时：exe 旁边（或系统路径）必须有对应 .dll
```

LearnOpenGL **官方 Windows 仓库**里常见 `lib/` + `dlls/`，就是这种思路的一种。  
本工程当前为了省事，用的是 **静态 `.a`**，所以**不需要**再单独准备一套 `dlls/` 目录。

## 3. 「源码接入」vs「预编译接入」

### 以前：源码接入（`add_subdirectory`）

```
Depends/assimp-5.4.3/   ← 整份源码
        │
        ▼  CMake 把 Assimp 也当成子工程
每次可能配置/编译 Assimp
        │
        ▼
和你的 main 一起链接
```

像「买面粉自己烤面包」——灵活，但第一次和 Reload 会慢。

### 现在：预编译接入（更接近官方「用现成库」）

```
Depends/prebuilt/lib/libassimp.a   ← 事先烤好
Depends/prebuilt/include/assimp/   ← 菜单
        │
        ▼  主工程只链接，不再编 Assimp 源码
main.exe
```

像「直接买面包」——Reload 和全量构建快很多。

> 注意：预编译库必须和你的 **编译器匹配**。  
> 本工程用 CLion 自带 **MinGW**。官方仓库里给 Visual Studio 的 `.lib` **不能直接**给 MinGW 用，所以我们用同一套 MinGW 自己 `install` 到了 `prebuilt/`。

## 4. 本工程依赖一览（对照）

| 依赖 | 类型 | 你怎么用 |
|------|------|----------|
| glad | 单个 `.c`，本工程当场编成静态库 | `add_library(glad ...)` |
| glfw | 预编译静态库 | 链接 `glfw3` |
| assimp | 预编译静态库 | 链接 `assimp` + `zlibstatic` |
| glm | 纯头文件 | `#include <glm/...>` |
| stb | 头文件 + 一个实现 `.cpp` | include + `stb_image_impl.cpp` |

`zlibstatic`：Assimp 内部用到的压缩库。以前源码内嵌时 CMake 会自动带上；改成裸 `.a` 后要在 `target_link_libraries` 里**显式写上**。

## 5. 小练习

1. `#include "Mesh.h"` 时，编译器是在「找说明书」还是「链接库」？  
2. 为什么只有 `libassimp.a`、没有对应头文件，写不出能编译过的调用代码？  
3. 静态链接后，把 `main.exe` 拷到另一台没装 Assimp 的电脑，一般还要不要带 `assimp.dll`？  
4. （思考）为什么换 MinGW 大版本后，可能要重新生成 `Depends/prebuilt/`？
