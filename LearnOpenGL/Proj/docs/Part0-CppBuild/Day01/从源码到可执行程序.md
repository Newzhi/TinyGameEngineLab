## 0. 术语中英对照

| 英文 | 中文 | 一句话 |
|------|------|--------|
| Source code | **源码** | 你写的 `.cpp` / `.h` 文本 |
| Compile | **编译** | `.cpp` → `.o` / `.obj`（机器码碎片） |
| Object file | **目标文件** | 编译产物，还不能单独当程序跑 |
| Link | **链接** | 把多个目标文件 + 库拼成一个程序 |
| Executable | **可执行文件** | Windows 上通常是 `.exe` |
| Build | **构建** | 配置 + 编译 + 链接这一整套 |
| Build directory | **构建目录** | 生成中间文件和 `.exe` 的地方（本工程常是 `cmake-build-debug`） |

---

## 1. 一句话流程

```
你写的 .cpp / .h
        │
        ▼  编译（Compiler，如 g++）
若干 .o / .obj
        │
        ▼  链接（Linker）
main.exe（可运行）
```

生活类比：

| 阶段 | 类比 |
|------|------|
| 源码 | 菜谱 + 食材清单（文字） |
| 编译 | 把每道菜分别炒好（还不成整桌宴席） |
| 链接 | 摆盘上桌，拼成完整一餐 |
| `.exe` | 端上桌、能吃的成品 |

---

## 2. 为什么要分「编译」和「链接」？

一个真实项目很少只有一个文件。本工程至少有：

- `main.cpp` —— 你的主程序
- `stb_image_impl.cpp` —— 图像加载实现
- `glad.c` —— OpenGL 函数加载
- 还有已经编好的 Assimp、GLFW 库……

如果每次改一行 `main.cpp`，都把 Assimp 几百个文件重新编译一遍，会非常慢。

所以工具链设计成：

1. **只重新编译改动过的 `.cpp`**（增量编译）
2. 最后再 **链接** 一次，把新 `.o` 和已有库拼起来

这就是为什么改一小行有时也要等几秒到十几秒——往往卡在「重编你这个重文件」或「链接出一个不小的 `.exe`」，不一定是 Assimp 又整库重编了。

## 3. 源码目录 vs 构建目录

本工程典型布局：

```
LearnOpenGL/
  Depends/          ← 第三方（源码 + 预编译库）
  Proj/             ← 你的工程源码
    src/
    shaders/
    Resource/
    CMakeLists.txt
    cmake-build-debug/   ← 构建目录（CLion 默认生成，一般不进 git）
      main.exe
      shaders/           ← 运行时读的着色器副本
      Resource/          ← 运行时读的资源副本
```

| 目录 | 你改什么 | 程序运行时用什么 |
|------|----------|------------------|
| `Proj/src/...` | 源码 | 不直接「读」源码，而是编进 `.exe` |
| `Proj/shaders/` | 着色器文本 | 通常用构建目录里的拷贝 |
| `cmake-build-debug/` | 一般不手改 | `.exe` 在这里跑，工作目录也常在这里 |

**重要**：改了 `shaders/model.fs` 之后，若构建目录里还是旧文件，画面不会变。本工程用 `POST_BUILD` 在每次 Build 后同步 `shaders/`，一般点 Build 即可，不必为了改着色器去 Reload CMake。

## 4. Debug 和 Release（知道即可）

| 配置 | 特点 |
|------|------|
| Debug | 带调试信息，`.exe` 更大，跑得慢一点，方便断点 |
| Release | 优化，更小更快，不好调试 |

CLion 默认常用 **Debug**。本仓库预编译的 Assimp/GLFW 也是按当前工具链编进 `Depends/prebuilt/` 的；换编译器大版本后可能要重编预编译库（见 Day03 / `Depends/README.md`）。

## 5. 小练习

1. 打开 `Proj/cmake-build-debug/`，找到 `main.exe`。它是「源码」还是「构建产物」？  
2. 改 `main.cpp` 里一行数字后点 Build：一般会重新编译哪个 `.cpp`？会不会把整个 Assimp 源码再编一遍？（提示：本工程现在用的是预编译 Assimp。）  
3. 程序运行时读的是 `Proj/Resource/...` 还是 `cmake-build-debug/Resource/...`？和「工作目录」有什么关系？
