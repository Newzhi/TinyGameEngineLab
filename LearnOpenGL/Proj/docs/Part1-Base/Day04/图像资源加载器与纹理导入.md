# 图像资源加载器与纹理导入（基于当前项目结构）

这份文档对应 Day 04 的准备工作。Day 03 你已经有了 **Shader 类 + 独立 shader 文件**，Day 04 的目标是：

1. 理解 **OpenGL 本身不会读图片文件**，需要额外的图像加载库
2. 把 **`stb_image.h`** 正确接入当前项目（放在 `src/headfile/`）
3. 知道 **`Resource/Texture/`** 目录怎么用，以及 **CMake 为什么要改**

> 本文档只讲「图像加载器导入」；真正把像素上传 GPU、在 Shader 里采样显示纹理，会在后续 Day 04/05 代码实践中继续。

---

## 1. Day 03 → Day 04：多了什么？

Day 03 的数据流：

```
顶点颜色 (VBO) → Shader → 屏幕
```

Day 04 要在此基础上增加：

```
图片文件 (jpg/png) → stb_image 解码 → CPU 像素数组 → OpenGL 纹理 → Shader 采样 → 屏幕
```

| 新增内容 | 位置 | 作用 |
|---------|------|------|
| `stb_image.h` | `src/headfile/` | 从磁盘读取并解码 PNG/JPG 等格式 |
| `stb_image_impl.cpp` | `src/cppfile/` | 激活 stb 的函数实现（整个项目只需一个） |
| `Resource/Texture/` | 项目根目录 | 存放纹理图片资源 |
| CMake 复制 `Resource/` | `CMakeLists.txt` | 构建时把资源复制到输出目录，运行时能按相对路径读取 |

---

## 2. 为什么需要 stb_image？

OpenGL 是渲染 API，**不负责文件 IO**，也**不会**帮你打开 `container.jpg`。

要把一张图片显示在三角形/矩形上，需要两步：

```
① 读文件、解码成像素     ← stb_image 负责（CPU 侧）
② 上传像素、创建 GPU 纹理  ← glGenTextures / glTexImage2D 负责（GPU 侧）
```

LearnOpenGL 官方教程选用 **`stb_image.h`**，因为它是 **单头文件库（single-header library）**：

- 从网上**只下载一个 `.h` 文件**
- 不需要额外链接 `.lib` / `.dll`
- 支持 PNG、JPG、BMP、TGA 等常见格式
- 用法简单，适合学习阶段

---

## 3. stb_image.h 放在哪里？为什么放 headfile？

你已确定把下载的文件放在：

```
Depends/stb/stb_image.h
```

和 `Shader.h` 同级，这样项目内第三方/工具类头文件都集中在 `headfile/`，结构一致：

```
src/headfile/
  Shader.h       ← 着色器封装
  stb_image.h      ← 图像加载库（第三方单头文件）
```

在其他代码里引用：

```cpp
#include "stb_image.h"
```

需要在 CMake 里把 `src/headfile` 加入头文件搜索路径（见第 6 节）。

---

## 4. 单头文件库的关键规则：STB_IMAGE_IMPLEMENTATION

`stb_image.h` 里**同时包含声明和实现**。如果每个 `.cpp` 都直接 `#include` 并打开实现，链接时会 **重复定义** 报错。

官方要求：**整个项目里，有且只有一个 `.cpp` 在 include 之前写：**

```cpp
#define STB_IMAGE_IMPLEMENTATION
#include "stb_image.h"
```

当前项目里这个文件是：

```
src/cppfile/stb_image_impl.cpp
```

内容：

```cpp
#define STB_IMAGE_IMPLEMENTATION
#include "stb_image.h"
```

### 各文件分工

| 文件 | 写法 | 说明 |
|------|------|------|
| `stb_image_impl.cpp` | 有 `#define STB_IMAGE_IMPLEMENTATION` | 编译 stbi_load 等函数的实现 |
| `main.cpp` 等 | 只 `#include "stb_image.h"` | 只使用声明，不重复定义实现 |

**千万不要**在 `main.cpp` 里再写 `#define STB_IMAGE_IMPLEMENTATION`。

## 5. Resource/Texture 资源目录

纹理图片不放进 `src/`，单独放在项目资源目录：

```
Proj/
  Resource/
    Texture/
      container.jpg      ← 教程常用示例（需自行下载放入）
      awesomeface.png
      README.md
```

### 为什么单独建 Resource？

- **和源码分离**：图片不是编译单元，不应和 `.cpp` 混在一起
- **和 shaders 一致**：shader 在 `shaders/`，纹理在 `Resource/Texture/`，职责清晰
- **便于 CMake 整目录复制**：和 `file(COPY shaders ...)` 同一套思路

### 运行时路径

代码里加载纹理时使用**相对于程序工作目录**的路径，例如：

```cpp
stbi_load("Resource/Texture/container.jpg", &width, &height, &nrChannels, 0);
```

工作目录通常是 CLion 的构建输出目录（如 `cmake-build-debug/`）。CMake 会把 `Resource/` 复制过去，所以运行时能找到 `Resource/Texture/...`。

## 6. CMakeLists.txt 需要改什么？

Day 03 的 CMake 只复制了 `shaders/`。Day 04 需要三处改动：

### 6.1 把 stb 实现文件加入编译

```cmake
add_executable(main
    src/glad.c
    src/cppfile/main.cpp
    src/cppfile/stb_image_impl.cpp    # 新增
    src/headfile/Shader.h
)
```

没有这一行，链接时会报 `undefined reference to stbi_load`。

### 6.2 把头文件目录 headfile 加入 include 路径

```cmake
target_include_directories(main PRIVATE
    ${CMAKE_CURRENT_SOURCE_DIR}/includes
    ${CMAKE_CURRENT_SOURCE_DIR}/src/headfile    # 新增
)
```

这样全项目可以直接：

```cpp
#include "stb_image.h"
#include "Shader.h"
```

而不必写 `../headfile/...` 相对路径。

### 6.3 复制 Resource 到构建目录

```cmake
file(COPY ${CMAKE_CURRENT_SOURCE_DIR}/shaders DESTINATION ${CMAKE_CURRENT_BINARY_DIR})
file(COPY ${CMAKE_CURRENT_SOURCE_DIR}/Resource DESTINATION ${CMAKE_CURRENT_BINARY_DIR})    # 新增
```

配置 CMake 后，构建目录里会有：

```
cmake-build-debug/
  shaders/
  Resource/
    Texture/
  main.exe
```

## 7. 核心 API 速查

| API | 作用 |
|-----|------|
| `stbi_load(path, &w, &h, &nrChannels, desired_channels)` | 加载图片，返回 `unsigned char*` 像素数组 |
| `stbi_image_free(data)` | 释放 `stbi_load` 分配的 CPU 内存 |
| `stbi_failure_reason()` | 加载失败时返回错误原因字符串 |
| `stbi_set_flip_vertically_on_load(true)` | 垂直翻转图像（OpenGL 纹理原点在左下，图片多在左上） |

### stbi_load 参数说明

```cpp
unsigned char* data = stbi_load(
    "Resource/Texture/container.jpg",
    &width,           // 输出：图片宽度（像素）
    &height,          // 输出：图片高度
    &nrChannels,      // 输出：原始通道数（1=灰度, 3=RGB, 4=RGBA）
    0                 // desired_channels：0=保持原样，3=强制 RGB，4=强制 RGBA
);
```

上传 OpenGL 纹理时，`nrChannels` 要对应正确的格式：

| nrChannels | glTexImage2D 的 format |
|------------|------------------------|
| 1 | `GL_RED` |
| 3 | `GL_RGB` |
| 4 | `GL_RGBA` |

### 典型使用模板（后续 main.cpp 会用到）

```cpp
#include "stb_image.h"

stbi_set_flip_vertically_on_load(true);

int width, height, nrChannels;
unsigned char* data = stbi_load("Resource/Texture/container.jpg",
                                &width, &height, &nrChannels, 0);
if (data) {
    // TODO: glGenTextures + glBindTexture + glTexImage2D + 生成 mipmap
    stbi_image_free(data);
} else {
    std::cout << "Failed to load texture: " << stbi_failure_reason() << std::endl;
}
```

```
                            │ Shader 里 sampler2D 采样（后续实现）
                            ▼
                         屏幕像素
```

## 9. 常见问题

| 现象 | 可能原因 |
|------|----------|
| `undefined reference to stbi_load` | 未把 `stb_image_impl.cpp` 加入 `add_executable` |
| `multiple definition of stbi_load` | 多个 `.cpp` 都写了 `#define STB_IMAGE_IMPLEMENTATION` |
| `Failed to load texture` | 图片路径错；或 CMake 未复制 `Resource/`；或文件未放进 `Resource/Texture/` |
| 纹理上下颠倒 | 加载前未调用 `stbi_set_flip_vertically_on_load(true)` |
| 找不到 `stb_image.h` | CMake 未把 `src/headfile` 加入 `target_include_directories` |
